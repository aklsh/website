# AGENTS.md — Hugo Website

## Project Overview
This is a Hugo static site generator project with:
- Content in Markdown format
- SCSS for styling
- Hugo templates in Go template syntax
- A Gemini capsule generated from the same Markdown

## Source of Truth
- `content/` is the only source for both the HTTPS site and the Gemini capsule. Keep content in Markdown; never maintain hand-written `.html` or `.gmi` copies.
- `public/` and `public-gemini/` are generated build output and are gitignored. Never edit them directly.
- Keep prose unchanged when the task is a theme, UI, layout, or refactor change; only edit content when explicitly asked.
- Images, PDFs, and other media stay on the HTTPS CDN (`cdn.aklsh.me`). The capsule links to them; do not copy binaries into the Gemini build.
- Math stays as `$...$` text. Gemini cannot render it, so leave it readable as plain text.

## Build and Test
Requires Hugo Extended, Python 3, make, and `md2gemini` (`uv tool install md2gemini`).

```sh
make build          # Hugo site + Gemini capsule
make http           # HTTPS site only, into public/
make gemini         # Gemini capsule only, into public-gemini/
make clean          # remove both build directories
```

- Always run `make clean && make build` after changes. Do not claim a change works without a clean build.
- `make gemini` runs a validator: every page must have one top-level heading, and every local `=>` link must exist. Fix failures instead of bypassing the validator.
- For live preview use the repo-local cache and bind to all interfaces so it is reachable over Tailscale:

```sh
HUGO_CACHEDIR=$(pwd)/.hugo_cache hugo server --bind 0.0.0.0 --port 1314
```

Use another port if 1313/1314 is occupied. Do not use `hugo server` without the repo-local cache.

## Hugo and Content Conventions
- Use Markdown and Hugo shortcodes. Raw HTML is disallowed by Goldmark's safe default; do not enable `markup.goldmark.renderer.unsafe`.
- Use Hugo's built-in `figure` shortcode for images, including the avatar (`class="avatar"`). Use the existing `art-links` shortcode for art downloads.
- When adding a shortcode that must appear in the capsule, add matching handling to `scripts/build-gemini.py`; otherwise the shortcode text leaks into the generated gemtext.
- Section index pages (`_index.md`) should have `title` and `description`: they drive both the HTML `<title>` and the capsule header. The home page uses `heading` and `handle` for its capsule title and handle.
- Prefer native Hugo constructs and deleting custom code over adding abstractions. Keep templates DRY with partials and keep the single CSS mapping in `baseof.html`.
- SCSS: BEM class naming, 2-space indentation, shared variables from `assets/scss/partials/_vars.scss`.
- Preserve accessibility: keyboard navigation, focus states, `aria-expanded` on the mobile menu, and semantic buttons.

## Gemini Capsule
- Generated by `scripts/build-gemini.py` using `md2gemini`; the output is a complete capsule in `public-gemini/`.
- Each page gets `# title`, `> description`, a back link, and root-relative links. The blog index is generated from post front matter and sorted by date; the home page links to About, Blog, and Art.
- Do not add hand-written `.gmi` files. If a layout or shortcode changes, update the generator and rerun the validator.
- The capsule is public at `gemini://gemini.aklsh.me/`.

## Deployment
- HTTPS: `make deploy-http` builds and rsyncs `public/` to `$(WEB_REMOTE):$(WEB_PATH)` (currently `aklsh@100.93.74.76:/home/aklsh/sites/website` over Tailscale). Cloudflare proxies the HTTPS site.
- Gemini: `make deploy-gemini` (alias `make deploy-fly`) rebuilds the capsule and runs `fly deploy --ha=false --depot=false` for the Fly app `aklsh-gemini` in `sin`.
- `make deploy` does both. `./deploy` is equivalent to `make deploy`. Deploy only when asked.

Fly/Gemini constraints:
- Keep `app = "aklsh-gemini"` in `fly.toml`. It is the Fly app name, not the public hostname; the hostname lives in the Dockerfile's agate `--hostname gemini.aklsh.me`.
- Keep exactly one Machine (`--ha=false`). The `gemini_certs` volume is attached to that Machine only; a second Machine would need a second volume and a synced certificate.
- Keep `--depot=false`; Depot hangs for this account.
- The capsule is IPv6-only: `gemini.aklsh.me` has an AAAA record and no A record. Do not add IPv4 or Cloudflare proxying.
- The Cloudflare record must stay DNS-only (grey cloud). Cloudflare's normal proxy handles only HTTP/HTTPS, while Gemini is raw TCP on 1965.
- Do not delete the `gemini_certs` volume or the files under `/certs/store/`. Agate serves a self-signed certificate from there; wiping it rotates the certificate and breaks TOFU trust in existing Gemini clients.
- Do not change `primary_region` casually: `maa` is unavailable and `bom` requires a paid plan. Moving regions requires a new volume and copying the certificates, not just a config edit.

## Design and UI
- The site uses IBM Plex Sans. The cyan `$secondary` (`#94ebeb`) is the accent and the text-selection/highlight color.
- Avoid magic pixel values and "overfit" measurements. Derive spacing from existing variables or font metrics, and verify visual changes in a real browser with the actual font loaded (or headless Chromium with the font injected).
- For visual work, run the Hugo server and inspect the built pages; screenshots or a live browser check are stronger evidence than reading CSS.

## Git
- Commit only when asked. When asked, make granular commits grouped by concern (content, templates, build, deploy) and verify each commit builds independently.
- Push to `origin/master` (GitHub) unless told otherwise. The `personal` remote points at athena and is separate from the Fly deployment.
- Never commit generated output (`public/`, `public-gemini/`), certificates, or caches.

## Output Variants
- `content/` is the source for both the https:// website and the gemini:// capsule.
- `make build` writes the Hugo site to `public/` and the capsule to `public-gemini/`.
